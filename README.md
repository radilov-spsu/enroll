# Регистрация на курс

Это репозиторий-заявка. Чтобы получить **личный приватный репозиторий** для работ по
предмету, вам нужно один раз сделать Pull Request в этот репозиторий.

Звучит страшно только первый раз — ниже пошаговая инструкция, где ничего не нужно
устанавливать: всё делается в браузере за 5 минут.

> **Результат:** после того как преподаватель примет вашу заявку, в организации
> автоматически создастся репозиторий вида `ivanov-ivan-ivanovich-2026`, доступный
> только вам и преподавателю. Ссылка придёт комментарием в ваш Pull Request и
> приглашение — на почту.

## Что такое Pull Request (коротко)

Вы не можете писать напрямую в чужой репозиторий. Поэтому схема такая:

```
  этот репозиторий          ваша копия              обратно сюда
  (org/enroll)   ──fork──►  (вы/enroll)  ──правка──► Pull Request ──► преподаватель мержит
```

1. **Fork** — вы делаете себе личную копию этого репозитория.
2. В своей копии добавляете один файл с вашими ФИО и группой.
3. **Pull Request (PR)** — предлагаете преподавателю забрать это изменение к себе.
4. Преподаватель нажимает Merge → робот создаёт вам репозиторий.

## Способ 1. Через браузер (рекомендуется)

Ничего устанавливать не нужно. Нужен только аккаунт на GitHub.

### Шаг 0. Заведите аккаунт и войдите

Если аккаунта ещё нет — https://github.com/signup. Запомните свой **логин**
(он же username) — он виден в правом верхнем углу и в адресе вашего профиля
`https://github.com/ВАШ-ЛОГИН`. Он понадобится дальше.

> Совет: сделайте логин человекочитаемым. `ivan-petrov` — хорошо, `xXx_killer_2007` —
> вам с этим ещё резюме показывать.

### Шаг 1. Сделайте fork

1. Откройте главную страницу этого репозитория.
2. Справа сверху нажмите кнопку **Fork**.
3. На открывшейся странице ничего не меняйте, нажмите **Create fork**.

Через пару секунд вы окажетесь в своей копии — в адресной строке будет
`github.com/ВАШ-ЛОГИН/enroll`, а под названием — надпись
*forked from …*. Дальше работаем **только в своей копии**.

### Шаг 2. Создайте файл заявки

1. В своей копии нажмите **Add file** → **Create new file**
   (кнопка справа над списком файлов).
2. В поле имени файла введите ровно:

   ```
   students/ВАШ-ЛОГИН.yml
   ```

   Например, если ваш логин `ivan-petrov`, то `students/ivan-petrov.yml`.

   > Слэш `/` в имени автоматически создаст папку `students` — так и надо.
   > Имя файла обязано совпадать с вашим GitHub-логином, иначе робот отклонит заявку.

3. В большое поле ниже вставьте и заполните:

   ```yaml
   last_name: Иванов
   first_name: Иван
   middle_name: Иванович
   group: БПИ-231
   ```

   ФИО — **по-русски, как в зачётке**. Транслитерацию для имени репозитория робот
   сделает сам. Если отчества нет — строку `middle_name` удалите целиком.

### Шаг 3. Закоммитьте файл

1. Прокрутите вниз до блока **Commit changes**.
2. В поле описания напишите что-нибудь понятное, например `Заявка: Иванов И.И.`
3. Оставьте выбранным **Commit directly to the `main` branch**.
4. Нажмите зелёную **Commit changes**.

### Шаг 4. Откройте Pull Request

1. Вверху страницы вашей копии перейдите на вкладку **Pull requests**.
2. Нажмите **New pull request**.
3. Откроется страница сравнения. Проверьте, что стрелка направлена **из вашей копии
   в исходный репозиторий**:

   ```
   base repository: radilov-spsu/enroll   base: main
        ◄── head repository: ВАШ-ЛОГИН/enroll   compare: main
   ```

   Ниже должен быть виден ровно один изменённый файл — ваш.
4. Нажмите **Create pull request**.
5. Заголовок оставьте или замените на `Заявка: Иванов Иван Иванович, БПИ-231`,
   заполните шаблон в теле и нажмите **Create pull request** ещё раз.

### Шаг 5. Дождитесь проверки

Внизу PR появится автоматическая проверка **Проверка заявки**:

- ✅ зелёная галочка — всё хорошо, ждите преподавателя;
- ❌ красный крестик — что-то не так. Нажмите **Details**, прочитайте сообщение об
  ошибке, исправьте файл в своей копии (вкладка Code → файл → карандаш → Commit
  changes). PR обновится сам, закрывать и создавать новый **не нужно**.

Когда преподаватель нажмёт Merge, в PR появится комментарий со ссылкой на ваш
личный репозиторий.

## Способ 2. Через git в терминале

Для тех, кому удобнее консоль. Нужен установленный [git](https://git-scm.com/downloads).

Fork всё равно делается кнопкой на сайте (шаг 1 выше) — или командой
[`gh`](https://cli.github.com/), если он у вас есть.

```bash
# 1. Клонируем СВОЮ копию (не оригинал!)
git clone https://github.com/ВАШ-ЛОГИН/enroll.git
cd enroll

# 2. Отдельная ветка — хороший тон
git switch -c enroll/ВАШ-ЛОГИН

# 3. Создаём файл заявки
mkdir -p students
cat > students/ВАШ-ЛОГИН.yml <<'EOF'
last_name: Иванов
first_name: Иван
middle_name: Иванович
group: БПИ-231
EOF

# 4. Коммитим и отправляем
git add students/ВАШ-ЛОГИН.yml
git commit -m "Заявка: Иванов И.И."
git push -u origin enroll/ВАШ-ЛОГИН
```

После `push` в терминале будет ссылка вида
`https://github.com/ВАШ-ЛОГИН/enroll/pull/new/enroll/ВАШ-ЛОГИН` — откройте её
и нажмите **Create pull request**.

Всё то же самое одной командой, если установлен GitHub CLI:

```bash
gh repo fork radilov-spsu/enroll --clone --remote
# ...создать файл, закоммитить...
gh pr create --fill
```

## Формат файла заявки

Путь: `students/<ваш-github-логин>.yml`

```yaml
last_name: Иванов        # обязательно, кириллицей
first_name: Иван         # обязательно, кириллицей
middle_name: Иванович    # необязательно — удалите строку, если отчества нет
group: БПИ-231           # обязательно
```

Имя будущего репозитория собирается так:
`фамилия-имя-отчество` транслитом + `-` + учебный год.

| ФИО | Репозиторий |
|---|---|
| Иванов Иван Иванович | `ivanov-ivan-ivanovich-2026` |
| Щербакова Юлия | `shcherbakova-yuliya-2026` |
| Хайруллин Ильдар Ринатович | `khayrullin-ildar-rinatovich-2026` |

Пример готового файла: [`students/_example.yml`](students/_example.yml).

## Что делать после принятия заявки

1. Примите приглашение: письмо на почте GitHub либо баннер **Accept invitation**
   при открытии ссылки на репозиторий. Без этого доступа не будет.
2. Склонируйте себе:
   ```bash
   git clone https://github.com/radilov-spsu/ваш-репозиторий.git
   ```
3. Откройте `README.md` внутри — там структура папок и правила сдачи работ.
4. Материалы курса лежат в отдельном публичном репозитории — ссылка в описании
   организации.

## Частые ошибки

**«PR должен добавлять ровно один файл»**
Вы случайно изменили ещё что-то (часто — README или файл другого студента).
Откатите лишние правки в своей копии и запуште заново.

**«Файл должен называться students/ВАШ-ЛОГИН.yml»**
Имя файла не совпадает с логином, или файл лежит не в папке `students`, или
расширение `.yaml` / `.txt` вместо `.yml`. Переименуйте: откройте файл →
карандаш → поправьте путь в поле имени сверху → Commit.

**«некорректный YAML»**
Чаще всего забыт пробел после двоеточия (`last_name:Иванов` — неверно,
`last_name: Иванов` — верно) или ФИО обёрнуто в кавычки-ёлочки.

**Стрелка PR направлена не туда**
На странице создания PR слева (`base`) должна быть **организация**, справа
(`compare`) — **вы**. Если наоборот — нажмите **switch base**.

**Сделал PR не в тот репозиторий / закрыл случайно**
Ничего страшного, просто откройте новый — старый закройте кнопкой Close.

**Изменил файл после создания PR — надо делать новый PR?**
Нет. Любой новый коммит в вашей ветке автоматически попадает в тот же PR.

**Ничего не получается**
Напишите комментарий прямо в своём PR или преподавателю — не стесняйтесь,
это первая задача курса, а не экзамен.
